# Supabase → Neon Migration Audit

This document is the pre-migration dependency map required before any Supabase code
or SQL is deleted. It was generated by:

```bash
git grep -n -I \
  -e '@supabase' \
  -e 'supabase' \
  -e 'auth.uid' \
  -e 'auth.users' \
  -e 'service_role' \
  -e 'NEXT_PUBLIC_SUPABASE' \
  -e 'SUPABASE_'
```

against the imported history from the original Supabase prototype
(`nikitaorgiya/servicedesk-lite`, branch `claude/servicedesk-lite-stage-1-hzf7vf`,
commit `67d09de`). 317 matching lines across 45 files, grouped below by category with
the concrete Neon replacement and migration status.

## Notes

- The original Supabase prototype is preserved unmodified at
  `nikitaorgiya/servicedesk-lite`, branch `claude/servicedesk-lite-stage-1-hzf7vf`,
  commit `67d09de`. Nothing in that repository was changed by this migration.
- `docs/database.md` and `docs/security.md` are left in the tree as historical
  design-rationale references (the reasoning behind constraints, RLS recursion
  avoidance, etc. still applies conceptually) but are no longer the operative
  documentation for this Neon-based codebase — see README.md instead.
- Deletion of `supabase/` happens only after the Drizzle schema, custom SQL
  migrations, and business logic in this document are all in place — never
  before, per the migration plan.
